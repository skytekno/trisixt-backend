# Connectivity parity: domains, imports, MCP, automation and public links

> Audit update (2026-09-20): this is an implementation map, not full-parity certification. Read the [confirmed gaps and acceptance scenarios](../RUST_PARITY_AUDIT.md) before relying on these coverage claims.

The Rust API retains the capabilities below. The persistence and HTTP contracts use UUID project/link/user identifiers instead of Rails integer/hashid identifiers. Migration tooling must maintain an explicit legacy-ID → UUID map; copying numeric identifiers into UUID endpoints is unsupported. Provider secrets are encrypted or stored as credential hashes, never returned by read endpoints.

## API and deployment mapping

- Domains: `/api/v1/projects/{uuid}/domain`, `/domain/availability`, `/domain/defaults`, `/domain/google_tracking_id`, `/custom_domains`, `/custom_domains/{primary|migration}`, `/custom_domains/preflight`, `/custom_domains/verify`.
- Imports: project `/migrations`, `/migration_source`, `/migration_source/test`, `/migration_source/backfill`, `/migrations/firebase`. The Firebase payload is `{ "csv": "...", "deeplink_prefix": "...", "short_link_prefix": "..." }`.
- OAuth: `/register`, `/authorize`, `/token`, `/revoke`, `/.well-known/oauth-authorization-server`, `/.well-known/oauth-protected-resource`. Send `resource=<PUBLIC_URL>/api/v1/mcp` on authorization and token requests. Dashboard consent POST remains `/api/v1/mcp/approve_consent`; it requires a live dashboard bearer credential and may restrict `project_ids`.
- MCP REST remains under `/api/v1/mcp/*`; direct JSON-RPC clients POST to `/api/v1/mcp`. `mcp:full`, `mcp:read`, `mcp:write` scopes are supported. Credentials granted before a newly created project do not automatically include that project; approve a new project scope.
- Server key lifecycle: `/api/v1/instances/{uuid}/server-keys[/{key_uuid}]`. Server SDK uses `PROJECT-KEY` and `ENVIRONMENT: production|test`; ordinary mobile SDK uses project-scoped `X-PROJECT-KEY`.
- Public assets may use uploaded S3/GCS asset URLs via the canonical storage API; link/branding/quick-link JSON supplies `image_url` instead of Rails multipart ActiveStorage attachment parameters. Store artwork is a bounded database cache served by `/api/v1/app-store/{platform}/{identifier}/artwork`.
- Browser cookies changed from Rails hashid cookies to project-bound, hashed `trisixt_visitor` tokens. Clipboard handoff uses a one-use `ct` token. This intentionally avoids trusting a raw device identifier from another tenant.

Set `CUSTOM_DOMAIN_MODE=manual` (default) with `DOMAIN_VERIFICATION_SECRET` of at least 32 characters, or `CUSTOM_DOMAIN_MODE=cloudflare` with `CLOUDFLARE_ZONE_ID`, `CLOUDFLARE_API_TOKEN`, and `CLOUDFLARE_SAAS_CNAME_TARGET`. Set `MIGRATION_ENCRYPTION_KEY` to a 32-byte hex key. Optional operator-only `BRANCH_API_ENDPOINT` and `APPSFLYER_API_ENDPOINT` overrides permit HTTPS or loopback HTTP for local tests; tenant input never controls the API endpoint.

Set `PUBLIC_URL` to the deployment issuer and `MCP_CONSENT_URL` to the authenticated dashboard consent page. `MCP_REGISTRATION_TOKEN` and `MCP_ALLOWED_REDIRECT_ORIGINS` can restrict registration. `ADMIN_API_KEY` protects the legacy automation endpoints. Separate application/server/project credentials are never interchangeable.

`domains::tick`, `imports::tick`, `app_metadata::tick` and `hardware::tick` are resumable worker hooks. Migration degraded/disabled alerts are queued for the common mail worker. Live Cloudflare zone/DNS/TLS operations, real Branch/AppsFlyer accounts, and live store artwork/CDN responses require operator infrastructure; local tests exercise their HTTP protocol and persistence paths without mutating a live cloud account.

## Protocol references

[Cloudflare custom hostnames API](https://developers.cloudflare.com/api/resources/custom_hostnames/), [hostname validation](https://developers.cloudflare.com/cloudflare-for-platforms/cloudflare-for-saas/domain-support/hostname-validation/), [Branch read link API](https://help.branch.io/apidocs/readexistingdeeplink), [AppsFlyer OneLink v2 read](https://dev.appsflyer.com/hc/reference/get-onelink-v2-link), [MCP authorization](https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization), [OAuth security best practice RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html), [Apple lookup API](https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/iTuneSearchAPI/LookupExamples.html), [scraper HTML parser](https://docs.rs/scraper/latest/scraper/), [Google Analytics page views](https://developers.google.com/analytics/devguides/collection/ga4/views), [Google tag CSP](https://developers.google.com/tag-platform/security/guides/csp).

Hardware model parity uses `hardware.rs` and `0036_connectivity_hardware.sql`: all 158 mappings from `AppleDeviceModels::NAMES` are retained, with unknown identifiers/marketing names/simulators unchanged. Android reads Google's fixed supported-devices CSV, accepts validated UTF-16LE/UTF-8, requires the exact four columns and at least 40,000 rows/20,000 model mappings, then swaps the PostgreSQL table in one transaction. Missing data returns the raw model and queues a refresh; a failed/truncated download never removes the last good table. The bounded worker refreshes weekly. Tests cover original-name passthrough, Unicode decoding, minimum-size rejection, first-match handling and database preservation. Google CSV live download depends on external connectivity and is distinct from local parser/persistence verification.

Provisioning keeps the explicit manual instance/project APIs and adds `/api/v1/instances/provision` for the original one-step setup. It returns separate production/test mobile keys and one server key exactly once. Pair hostnames now use `<random>.SERVER_HOST` and `<random>-test.SERVER_HOST`; both project redirect configurations share the generated URI scheme. Existing organization invitation endpoints add members after provisioning. MCP-created projects require consent for the new project IDs before subsequent tool access.

Automation now shares canonical analytics facts: all eight countable event counters, time-spent milliseconds, unique users, frozen link/referral scope and signed USD-cent ledger revenue. `total_*` aliases retain the Rails statistics names. The scoped query honors the instance retention entitlement and excludes unrelated projects/inviters, including after an attributed link is deleted. Provider deletion uses `Analytics::purge_project`: synchronous ClickHouse project mutations and polled BigQuery parameterized DELETE; durable external cleanup tombstones reconcile late Pub/Sub export deliveries.

`domain/defaults` returns `generic_title`, `generic_subtitle`, and `generic_image_url`, honoring `DEFAULT_LINK_TITLE`, `DEFAULT_LINK_SUBTITLE`, and `DEFAULT_SOCIAL_PREVIEW_URL`. The image is null unless an operator supplies a valid HTTP(S) asset URL; Rust does not advertise an unserved Rails asset or retain its old product logo. MCP platform fallbacks use the same safe custom-scheme validation as native project configurations. Link `avg_engagement_time` is the sum of canonical nonzero session durations divided once by engaged-session count and 1000, rounded to two decimal seconds; bounce-only links return zero. The native analytics and MCP routes share this implementation and its engaged/bounce test.
