# Analytics parity

> Audit update (2026-09-20): this is an implementation map, not full-parity certification. Read the [confirmed gaps and acceptance scenarios](../RUST_PARITY_AUDIT.md) before relying on these coverage claims.

The native implementation is `src/analytics_api.rs`, with the canonical view and JSON filter function in migration `0040_attribution_analytics.sql`. Dashboard reads use the durable PostgreSQL event and purchase ledgers. ClickHouse and Pub/Sub → BigQuery receive the same event schema asynchronously; a delayed delivery does not turn a successful event ingestion into an empty dashboard. Warehouse delivery and external IAM validation are documented separately.

| Existing Rails behavior | Native implementation and evidence |
| --- | --- |
| Events list/detail, timestamp/type/name/platform sorting, search, cursor pagination and exact count | `/api/v1/projects/{id}/analytics/events`, `/{event_id}`; legacy POST `events/search` and `events/sorted` aliases. Stable timestamp/event UUID tie-breakers; cursors bind project, query, filter and sorting context. List responses omit full properties; detail returns the event payload. Tenant isolation, ordering, invalid input and cursor tests in `tests/analytics.rs`. |
| Attribute/property/user-attribute filters and field pickers | Typed field discovery at `analytics/events/fields`; static attributes, bare property paths, explicit `properties.` paths and `user.` snapshots. Nested object paths, scalar string comparisons, `is`/`is_not` arrays, short `f/o/v` and object shorthand are supported. Field-value cursors use lexical ordering, date scope and project-bound labels for visitor/link/campaign IDs. Internal ingestion snapshots are excluded from discovery. |
| Timezone-aware event volume | `analytics/events/volume`; hourly, daily, Sunday-weekly and monthly buckets, with search and filters. Golden UTC → Asia/Jakarta boundary test verifies the hour bucket. |
| Overview countable users, new/returning users and event counters | `analytics/overview/key-metrics`, legacy `dashboard/metrics_overview`/`events/overview`. Countable events are VIEW, OPEN, INSTALL, REINSTALL, TIME_SPENT, REACTIVATION, APP_OPEN and USER_REFERRED. New users require an install in the range and first countable activity in the range; custom-only visitors do not inflate totals. Earlier history is scoped to the selected platform. Returning rate is a fraction; referred users count referral events. Golden fixture includes cross-platform history, reinstall-only/custom-only activity and repeated referrals. |
| Zero-filled metric series and prior-period trends | `analytics/overview/key-metrics/series` and `/trends/users`; local calendar-day buckets, equally sized prior period clamped to retention, zero-filled missing days, first-activity new-user buckets. Revenue, units, cancellations, payers and first-time purchasers use the signed purchase ledger. Monetary series/overview values use integer USD cents; unconverted transactions remain visible. Revenue timezone and trend goldens. |
| Version summary/distribution | `analytics/overview/versions` and `/versions/distribution`; top versions per platform, counts/percentages, earliest observed release date and Unknown labels. Desktop/mac/windows/linux normalize to web. Endpoint and release-date tests. |
| Source breakdown and immutable attribution | `analytics/overview/sources/breakdown`; campaigns → referrals → API links → links → organic priority. Ingestion freezes trusted link/campaign/tracking metadata and user attributes. Later link edits, deletion and visitor profile updates cannot change historical attribution. Frozen source/deleted-link and snapshot-filter regression tests. |
| Retention D1/D7/D30, median lifetime and cohort sparkline | `analytics/retention/summary`; maturity uses the actual first-seen timestamp, return status uses last event's local date, filters select lifetime matching visitors, and platform scopes first/last history. Visitor profile `last_seen_at` is not a substitute for actual activity. Golden fixtures distinguish UTC/Jakarta midnight, profile updates, immature/null cohorts and later matching events. |
| Session list/detail, synthetic sessions, summary filters, conversions | `analytics/sessions`, `/{opaque_key}`. Keys include project, canonical visitor, UTC day and SDK/synthetic session. Blank runs stitch forward to the next SDK session within a continuous 30-minute interval; disconnected runs get stable synthetic IDs. Latest device/platform/version/country and first attribution are aggregated before summary filtering. Real BUY ledger rows determine conversion and gross revenue; install events alone do not. Session tests cover reused IDs across visitors/days, blank-event detail, full-session filters, gaps and purchase matching. |
| Link/campaign/visitor summaries and legacy dashboard aliases | `/analytics/links`, `/campaigns`, `/visitors`; `dashboard/top_links`, `dashboard/links_views`, visitor aggregation/metrics aliases. Shared canonical facts and tenant authorization also feed management statistics and exports. |
| Retention and query-budget limits | Shared date/timezone validation, 90-calendar-day aggregate limit, hot/cold retention policy, active/nonterminal paid subscriptions or active enterprise grants. Expired/canceled subscriptions do not unlock longer history. Unsupported cold-window exclusion/substring filters are rejected. SQL reads have a 15-second statement timeout; budget exhaustion returns 422 and unavailable database connections return 503. Invalid inputs fail explicitly rather than returning empty success. |

The Rust schema uses UUID identifiers; cursors and session keys are opaque and are not interchangeable with Rails integer IDs/cursors. List responses provide `data` and legacy `events`/`sessions` aliases where applicable; field discovery provides legacy `{name,type}` entries and a `names` convenience alias. Filters accept JSON arrays/objects in POST bodies or URL-encoded JSON on GET requests. Full single-event properties are deliberately separate from list payloads. Existing data requires the documented Rails-to-native migration, including identifier mapping, before comparing production dashboards.

Run `TEST_DATABASE_URL=... cargo test --test analytics -- --include-ignored`. Eight database integration tests include the legacy golden scenarios described above; they are not a claim that every retained Ruby test executes against Rust. Large production-volume load testing and live cloud IAM acceptance remain environment-specific validation steps.
