# Configuration, operations and tenant lifecycle audit

Read-only source review, 2026-09-20. No tests, application starts, network/provider changes or source fixes. Executed only the read-only dependency inspection `cargo tree --locked -e features -i redis` in addition to source reads. All seven findings are supported, with qualifications below.

| ID / priority | Confirmed gap and paired source evidence | Acceptance case |
|---|---|---|
| O1 / P1 | Self-hosted public-registration policy is lost. Rails `app/controllers/api/v1/users_controller.rb:4-8` refuses registration when self-hosted. Native `src/accounts.rs:145-178` checks SSO policy, an email rate limit and `DISABLE_REGISTRATION=true` only (`:155-158`), then inserts the account; it never checks `TRISIXT_SELF_HOSTED`. This is a default-policy change, not absence of a registration-disable option. | Start with `TRISIXT_SELF_HOSTED=true` and registration override unset; both `/auth/register` and the native `/api/v1/users` registration alias should follow the agreed self-hosted policy. Invitation acceptance must remain token-authorized and usable. Also test explicit SaaS/default behavior and the independent disable flag. |
| O2 / P1 | Production IP throttling is not retained. Rails `config/initializers/rack_attack.rb:30-58` has production-only general IP, login IP and sensitive-request IP policies, plus SSO/MCP and SCIM/token rules (`:62-104`). Native `src/routes.rs:14-47` layers request tracing and CORS only; rate-limit call-site search across `src/` found email/account/token/project/global buckets rather than caller-IP limits. Examples: `src/accounts.rs:155,192,584`; `src/mcp.rs:105,314,449`. Native `src/auth.rs:29-68` DOES bound Argon2 jobs with a four-permit semaphore. Therefore do not claim no throttling or unbounded concurrent password hashing. | Send sequential requests from one IP while rotating addresses/client IDs, then multiple legitimate clients from different IPs. Verify login, signup/reset, SSO, MCP registration/authorization and SCIM policies, bounded 429 behavior, recovery and trusted-proxy handling. External ingress limits can satisfy an explicitly documented deployment requirement, but none were established by this code audit. |
| O3 / P2 | The retained OpenTelemetry integration has no native equivalent. Rails `config/initializers/opentelemetry.rb:1-5,22-40,84-98` configures instrumentation and optional OTLP trace export outside dev/test; resources identify service/process/host, and request/database/Redis/jobs/HTTP instrumentation is selected at `:39-81`. `app/services/trisixt/metrics.rb:17-27,38-53` defines counter/histogram hooks with a null fallback; callers include `app/services/clickhouse_write_service.rb:364` and `app/services/first_hit_migration.rb:72`. Rust `src/main.rs:8-12` initializes formatted tracing only, `src/routes.rs:39-44` adds HTTP log spans, and `Cargo.toml:22-23` provides tracing/subscriber but no OTEL exporter/metrics integration. QUALIFICATION: retained trace exporting is conditional; the metrics wrapper alone does not prove a configured metric exporter or successful historical metric delivery. | Configure the intended OTLP collector and prove a request, outgoing provider call, database operation and background job can be correlated; emit a failure and confirm exception/service attributes. Verify required latency/error/queue metrics arrive. If logs/SQL health replace this intentionally, document and accept the operational feature reduction. |
| O4 / P2 | Diagnostics retain routes but lose dependency probes and the dedicated read-only monitoring credential contract. Rails `app/controllers/api/v1/diagnostics_controller.rb:97-103,301-320` reports Redis queue errors and actual ClickHouse availability/disk queries independently. Its diagnostic exercise runs Redis ping/set/get at `:205-228`; dedicated auth uses `DIAGNOSTICS_API_KEY` with X-Diagnostics-Key/Bearer at `:323-333`. Native `src/operations.rs:39-46` returns PostgreSQL queue counts and stored job health; both health_metrics and test_diagnostics map to this same read at `:148-151`. Native auth instead uses `TRISIXT_ADMIN_KEY`/`ADMIN_API_KEY` and x-admin-key/x-auth (`:14-23`), the same key used for repair mutations (`:54-59`). `/up` exists and `/ready` queries PostgreSQL (`src/routes.rs:4-17`); neither probes Redis/warehouse/storage. Do not claim no health endpoints or that historical Rails health proved GCS/S3 readiness. | Stop each dependency separately. Health output should identify current failed subsystem versus stale worker history and not equate PostgreSQL readiness to provider readiness. Verify monitoring credentials cannot invoke flush/reconcile/retention mutation. Migrate existing header/key clients deliberately. |
| O5 / P1 for TLS-only Redis | Native Redis client cannot use TLS despite the Redis server image including TLS. Rails `lib/trisixt/redis_ssl.rb:4-20` supports rediss with peer verification and custom CA; diagnostics uses it (`app/controllers/api/v1/diagnostics_controller.rb:207`). Rust `Cargo.toml:30` enables redis `tokio-comp` only. Current `cargo tree --locked -e features -i redis` confirms redis 0.32.7 has no tls-native-tls/tls-rustls/tokio TLS feature enabled. The installed locked crate `redis-0.32.7/src/connection.rs:365-392` explicitly returns InvalidClientConfig for rediss without TLS. `src/worker.rs:64-66` discards Client::open failure with `.ok()`; `:44-53` does nothing and logs no warning when client is None. QUALIFICATION: Redis is now a disposable heartbeat; the PostgreSQL event queue remains durable (`src/worker.rs:1-2,12-41`). | Connect worker to an authenticated TLS Redis fixture with trusted CA, verify heartbeat and reconnect/expiry, reject wrong CA/hostname, and verify malformed/unsupported Redis URLs are surfaced. A provider failure must not lose PostgreSQL queued events. |
| O6 / P2 | Atomic initial member provisioning is missing from the native one-step provision API. Rails `app/controllers/api/v1/instances_controller.rb:20-26` passes members and returns self-hosted invite links; `app/services/instance_provisioning_service.rb:16,33-60` creates members inside the same transaction as the instance/projects. Native `src/provisioning.rs:11-15` denies unknown input and accepts only name; transaction `:42-99` creates owner plus paired projects/keys with no initial members. Separate invitation endpoint DOES exist (`src/accounts.rs:1182`), so inviting members is retained; atomic create-with-members and its response are not. | Provision with a list of existing and new member emails/roles; ensure all members and invitation obligations commit with the pair, invalid member rolls back the entire requested operation, and credentials are returned once. If separate calls are accepted product behavior, test retry/compensation and update clients instead of claiming one-step parity. |
| O7 / P2 | Organization rename no longer updates paired project names. Rails `app/controllers/api/v1/instances_controller.rb:61-69` atomically names production `name` and test `name-test`. Native provisioning initially uses the same convention (`src/provisioning.rs:59-65`), but `src/core_api.rs:109-125` updates only `instances.name`. | Provision `Alpha`, rename to `Beta`, verify organization and production/test project displays, listing/search and returned state follow the agreed naming convention atomically; cover independently renamed/custom project names if those are intentionally supported. This is a behavioral consistency difference, not an inability to edit project names separately. |

## Evidence boundaries

- O3 should say missing OTLP tracing integration and metrics instrumentation parity, not that a working Rails metrics exporter was proven.
- O4 should say live Redis/warehouse diagnostic probes and credential separation are missing; existing liveness/readiness/job-health features remain.
- O5 affects TLS Redis heartbeat connectivity, not PostgreSQL queue durability. Cargo feature output and locked dependency source confirm the unsupported rediss path without needing a live endpoint.
- O6 and O7 may be deliberate product changes, but no implementation-level parity exists for the specified old behavior; they need explicit scope acceptance or implementation.
